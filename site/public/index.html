Montage captures reconstructible Omarchy state into private, local-first vault history; maintains shareable multi-loadout repositories; and previews every restore or apply before mutation.

# capture and inspect immutable history
$ mntg backup
$ mntg backup list

# restore one exact snapshot
$ mntg restore --backup before-reinstall

Install

$ omarchy plugin add https://github.com/tombychowski/omarchy-montage --enable
$ ~/.config/omarchy/plugins/tombychowski.montage/bin/mntg link
$ mntg doctor

No install hook, no account, and no hosted control plane. The plugin id is tombychowski.montage; the command is mntg.

Two repositories, two jobs

Private vault

Selected configuration, inventory, optional encrypted secrets, labels, and immutable backup commits. Keep the GitHub remote private.

Loadout library

Multiple stable, shareable items for packages, pinned plugins, reconstructible web apps, and one theme—no arbitrary commands or dotfiles.

$ mntg repository sync personal
$ mntg share --repository personal --loadout minimal
$ mntg apply https://github.com/you/omarchy-loadouts.git --loadout minimal --dry-run

Trust boundaries

Preview and consent

Overwrite confirmation never answers AUR-build or persistent-service questions.

Preserve first

Restore is additive and keeps replaced files as *.montage-bak.

Conservative Git

Fast-forward pull and ordinary push only. Divergence is decision-required; no force-push or reset.

CLI authority

The panel consumes versioned mntg output and never interprets Git or repository files.

Moving from Ress

Montage is a separate plugin with separate commands and data. It can be installed beside Ress, then explicitly port selected Ress v1 artifacts into new Montage repositories.

$ mntg port ress inspect /path/to/ress-vault --json
$ mntg port ress plan /path/to/ress-vault --destination /path/to/montage-vault --json

There is no shared-live-directory mode and no automatic migration. Sources remain untouched; representational loss and self-plugin choices are explicit.
