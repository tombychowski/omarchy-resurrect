# Proposal

## Why

Independent review of the uncommitted Loadout-only transition found publication and recovery regressions, broken panel workflows, and inadequate failure evidence. It also reproduced inherited package-observation and dry-run provenance defects that violate the retained safety guarantees.

## What Changes

- Validate destination ancestors centrally and refuse overlapping Ress source/library trees before publication.
- Preserve schema-1 publication journal compatibility without restoring removed product functionality.
- Represent failed package inventory as unavailable rather than absence, preventing fabricated cleanup authority.
- Restore valid unhealthy-result handling, Ress protocol compatibility, keyboard field focus, and applied-loadout composition.
- Keep update previews from changing authoritative applied provenance; report first-read migration through all consumers; correct directory diagnostics.
- Add targeted failure and producer-to-consumer tests, reconcile contracts and obsolete wording, and remove unused unit fixtures.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `loadout-repositories`: destination containment, schema-1 recovery compatibility, and complete first-read migration reporting.
- `ress-loadout-migration`: source/library separation including ancestor overlap.
- `loadout-preservation`: unavailable package inventory cannot grant cleanup authority; previews preserve applied provenance.
- `panel-integration`: process outcomes and real CLI payloads preserve usable unhealthy/migration results; existing keyboard and composition guarantees remain required.
- `cli-consumer-protocol`: accurate file/directory diagnostics and migration reporting without stray protocol output.

## Impact

Repository transactions, Ress import, package observation/resource inspection, lifecycle previews, migration output, Model/Service/Panel, focused shell and consumer tests, repository/registry/CLI contracts, panel workflows, and testing evidence. No new dependency, Git history change, or restoration of Backup/Restore is proposed. Rendered keyboard/layout and real package effects remain disposable-VM evidence.
